# 第一篇：认识 Arduino UNO Q

## 本篇目标

建立从 Arduino 发展脉络到 UNO Q 双处理器开发模型的整体认知，能够区分硬件控制、Linux 应用和两侧协同的学习边界。

## 阅读顺序

先阅读[第 1 章：Arduino 的发展](./第1章_Arduino的发展.md)，再依次阅读[第 2 章：什么是 Arduino UNO Q](./第2章_什么是Arduino_UNO_Q.md)、[第 3 章：UNO Q 的硬件架构](./第3章_UNO_Q的硬件架构.md)、[第 4 章：UNO Q 的软件架构](./第4章_UNO_Q的软件架构.md)和[第 5 章：第一个实验——Blink 验证闭环](./第5章_第一个实验_Blink验证闭环.md)。

## 前置知识

具备基本电脑操作、命令行、Git 和编程概念；不要求先掌握 STM32、Linux 或 Python。涉及具体工具和硬件操作时，以对应章节标注的前置条件为准。

## 章节地图

- [第 1 章：Arduino 的发展](./第1章_Arduino的发展.md)——Arduino 的入门模型、AVR 时代、32 位与联网能力，以及走向 UNO Q 的路线背景。
- [第 2 章：什么是 Arduino UNO Q](./第2章_什么是Arduino_UNO_Q.md)——明确 UNO Q 在高性能 Linux 计算与实时硬件控制之间的定位。
- [第 3 章：UNO Q 的硬件架构](./第3章_UNO_Q的硬件架构.md)——说明 MPU、MCU 及其协同边界；完整规格和外设细节留给后续篇章。
- [第 4 章：UNO Q 的软件架构](./第4章_UNO_Q的软件架构.md)——说明 Linux、Arduino/Zephyr、开发工具与 Bridge/RPC 的分工；具体操作留给对应篇章。
- [第 5 章：第一个实验——Blink 验证闭环](./第5章_第一个实验_Blink验证闭环.md)——用源码、编译、上传、LED 观察和 App Lab 日志建立分层证据链。

## 实验与工具边界

本篇建立认知和首个实验的验证入口，不替代 STM32 外设、Linux 运维、Python Bridge、App Lab、视觉、AI、IoT 或综合项目教程。未实机验证的内容必须标注为待硬件验证，不将静态检查描述为运行结果。
