# 第七篇第5章设计：端侧推理性能评估

## 已确认范围

- 章节标题：**端侧推理性能评估：从测量方案到资源预算**。
- 本章承接第七篇第4章的推理回归，转向目标部署前的性能测量方法；解释冷启动、预热、稳态推理、端到端流程和资源观测不能混为一个数字。
- 配套实验只读取人工合成的测量记录，由 Python 标准库离线生成报告；不得加载模型、运行 ONNX Runtime、调用 UNO Q、采集真实硬件数据或触发设备动作。
- 样例指标包含预热与正式测量阶段、最近秩（nearest-rank）P50/P95、最大推理时延和观测到的 RSS；定义所有统计范围和量化方法，不设置通用性能门槛。
- JSON 顶层字段固定为 `schema_version`、`run_id`、`environment`、`warmup_count`、`measured_count`、`samples`；环境字段固定为 `platform_id`、`os_image_id`、`runtime_id`、`execution_provider_id`、`artifact_id`、`input_shape`、`batch_size`、`thread_count`。样本字段固定为连续的一基 `index`、`phase`（`warmup`/`measured`）、正的有限 `latency_ms` 和正的有限 `rss_mib`。
- 先出现的 `warmup_count` 条必须全标为 `warmup`，后续 `measured_count` 条必须全标为 `measured`；数组长度必须等于两者之和。拒绝缺失/多余字段、错误类型、非有限/非正测量值、错序和不匹配计数。正式时延与观测 RSS 只从 measured 样本统计。
- 对升序样本 `x` 和分位数 `p`，最近秩定义为 `x[ceil(p*n)-1]`，其中 `p` 是 0～1 的比例；报告标注该方法，不混用其他库的插值定义。
- 报告恒为 `REPORT_ONLY`，同时声明未使用通过阈值；结构错误阻断并返回非零退出码。报告不是模型质量、目标兼容、UNO Q 性能或部署验收结论。
- 图号使用全书下一号 Fig-47。正文 Mermaid 和独立 `.mmd` 源应一致，并在图示资源登记中明确来源、SVG 未渲染的状态。
- 正文按 `docs/writing-guidelines.md` 的章节元数据、代码说明、章节顺序和引用规范编写；新增官方资料只登记链接及原创摘要。

## 技术事实边界

- ONNX Runtime 官方性能指南将时延、吞吐量、内存利用率及模型/应用大小列作常见性能维度；这不意味着该运行时已在本书目标硬件上得到验证。
- ONNX Runtime profiling 工具可给出执行过程的详细性能事件；诊断 trace 与最终基准数字应分开解释。
- Python `time.perf_counter_ns()` 是用于测量短时区间的高分辨率计数器；绝对参考点无意义，应比较两次调用之差。
- 本章采用“最近秩”明示分位数定义，作为本书离线教学报告的约定，而不是上述产品或运行时的强制标准。

## 验收标准

1. 章节纳入第七篇目录，文档中所有内部相对链接均能解析。
2. 分析器拒绝不完整、矛盾、非有限或类型错误的输入；预热数据不混入正式时延统计。
3. P50/P95 由明示的最近秩算法计算，测试包含手工可核验的固定期望。
4. 对有效数据输出 `REPORT_ONLY`，无论数字高低都不判定通过或失败；对无效数据输出 `BLOCKED` 并以非零状态退出。
5. Mermaid 独立源与正文代码块一致；全书图号唯一。
6. 全量 Python 行为测试和仓库一致性检查通过；记录本机、来源、SVG 与实机验证边界。
